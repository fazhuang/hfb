# 00 Acceptance Specification — 验收规范

---

> **版本:** V0.1
> **状态:** Draft
> **适用范围:** QA · 安全 · 全体开发
> **维护者:** 技术负责人

## 1. 验收原则

1. **文档先行，代码在后** — 每个 Sprint 先验收文档完整性，再验收代码功能
2. **AI + 人工双审** — 自动化验收 + 人工抽查结合
3. **不可降级** — 验收标准只升不降，不因进度压力放松
4. **溯源必查** — 所有 AI 输出必须可追溯到原始文献

## 2. 验收层次

### 2.1 文档验收（每个 Sprint 必做）

| 检查项               | 工具           | 通过标准                |
| -------------------- | -------------- | ----------------------- |
| 新增文档符合模板规范 | Codex 审计     | 无 Critical 问题        |
| 文档交叉引用链接有效 | 自动化链接检查 | 无 404                  |
| 图表有对应源文件     | 人工           | Mermaid 源文件可渲染    |
| API 有完整文档       | 人工           | 每个端点有请求/响应示例 |

### 2.2 代码验收（每个 PR 必做）

| 检查项       | 工具            | 通过标准       |
| ------------ | --------------- | -------------- |
| 类型检查通过 | mypy strict     | 0 error        |
| Lint 通过    | Ruff            | 0 error        |
| 单元测试通过 | pytest          | 全绿           |
| 覆盖率       | pytest-cov      | ≥ 80% 领域逻辑 |
| 安全扫描     | Bandit / Safety | 无高危         |

### 2.3 功能验收（每个 Story 必做）

| 检查项           | 通过标准               |
| ---------------- | ---------------------- |
| API 响应格式正确 | 符合 API 文档定义      |
| 数据完整性       | 写入后读回一致         |
| 错误处理         | 异常输入返回正确错误码 |
| 分页             | offset/limit 行为正确  |
| 软删除           | 标记删除，不可检索     |

### 2.4 AI 验收（AI 模块必做）

| 检查项     | 通过标准               |
| ---------- | ---------------------- |
| RAG 溯源   | 每条断言有出处段落     |
| 检索召回率 | Recall@5 ≥ 0.85        |
| 生成忠实度 | Faithfulness ≥ 0.80    |
| NER 准确率 | F1 ≥ 0.85              |
| 模型卡完备 | 生产模型 100% 有模型卡 |

### 2.5 UI 验收（UI 变更必做）

| 检查项          | 通过标准                |
| --------------- | ----------------------- |
| Gemini 学术评审 | 无 Critical 问题        |
| 色彩检测        | 不超过 5 种主色同时出现 |
| 字体检测        | 古籍原文使用衬线体      |
| 键盘可访问      | Tab 可遍历所有交互元素  |
| 屏幕阅读器      | 所有图标有 aria-label   |

### 2.6 安全验收（每个 Sprint 必做）

| 检查项   | 通过标准                |
| -------- | ----------------------- |
| 认证有效 | 未认证请求返回 401      |
| 授权有效 | 无权访问返回 403        |
| 输入校验 | SQL 注入 / XSS 防护有效 |
| 密钥检查 | 代码中无硬编码密钥      |
| 依赖漏洞 | 无已知高危 CVE          |

## 3. 验收流程

```
开发完成
  → 自测（按本规范逐项检查）
  → Codex 文档审计
  → CI 自动化检查（类型/Lint/测试/覆盖率/安全）
  → 人工 Code Review
  → Gemini UI 评审（涉及 UI 变更时）
  → QA 功能验收
  → Sprint 验收通过
```

| UI 验收  | ✅ / ❌ |      |
| 安全验收 | ✅ / ❌ |      |

## 后续维护说明

- 每个 Sprint 结束后评审本规范是否需要更新
- 验收标准随系统成熟度提升
- 新增检查项向后兼容（不影响已有验收结果）
