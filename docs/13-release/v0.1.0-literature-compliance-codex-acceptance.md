# v0.1.0-literature-compliance Codex 严格验收报告

验收日期：2026-07-11
验收角色：独立发布审计员 / 生产上线验收工程师 / 数据采集安全审计员
验收范围：当前 `master` 工作区、当前 `HEAD`、未提交 release 归档与试运行脚本

## 1. 最终结论

**FAIL**

当前版本不允许作为 `v0.1.0-literature-compliance` 发布归档进入小规模真实数据试采集。主要阻塞原因：

1. Git tag `v0.1.0-literature-compliance` 不存在，但 release 文档声明存在。
2. release 文档、上线清单、操作手册、dry-run 脚本和测试均为未跟踪文件，未进入 `HEAD`。
3. 工作区不干净，且存在未提交的后端 API / pytest 配置改动。
4. `uv run ruff check .` 失败 20 项；`git diff --check` 失败。
5. 来源白名单仅为政策/配置，未接入采集运行时门禁。
6. 试采集种子缺少指令要求的若干核心/英文关键词，且真实 Crossref dry-run 样本噪声高。
7. dry-run 脚本自身零业务写入通过实测，但生产采集入口 `scripts/run_ingestion.py` 仍默认真实写入，且核心 `ingest()` 无 `dry_run` 参数。

## 6. 问题清单

### P0：阻塞试运行

1. Tag 不存在但 release 文档声明存在
   证据：`docs/13-releases/v0.1.0-literature-compliance-release.md:24-27`；`git show v0.1.0-literature-compliance` exit 128。
   影响：无法证明归档点、回滚点和验收对象一致。
   复现：运行 `git tag --list`、`git show v0.1.0-literature-compliance`。
   最小修复建议：提交所有 release 归档文件和脚本后，在对应 commit 创建并验证 tag；更新 release 文档 commit/tag。

2. Release 产物未提交，工作区 dirty
   证据：`git status --short --branch --untracked-files=all` 显示 release 文档、脚本、测试均未跟踪，且 `day2_search.py` / `backend/pyproject.toml` 已修改。
   影响：当前 `HEAD` 不包含 Claude 声称的归档和 dry-run 能力。
   复现：运行 `git status --short --untracked-files=all`。
   最小修复建议：将本轮应发布文件纳入一次明确 commit；无关/临时产物不提交；重新跑终检。

3. Lint 与 diff-check 不通过
   证据：`uv run ruff check .` exit 1，20 errors；`git diff --check` exit 2。涉及 `scripts/trial_run_ingestion.py:31-33`、`scripts/run_ingestion.py:13-15`、`tests/unit/test_trial_run.py:7/25`、`apps/backend/app/api/v1/day2_search.py:31` 等。
   影响：不满足发布质量门禁，且本轮新增脚本/测试自身带 lint 问题。
   复现：运行 `uv run ruff check .` 和 `git diff --check`。
   最小修复建议：只修 lint/空白，不改变合规逻辑；修完重跑测试。

4. 默认 dry-run 只覆盖新 trial 脚本，不覆盖所有采集入口
   证据：`scripts/trial_run_ingestion.py:118-123` 默认走 `_dry_run()`；但 `scripts/run_ingestion.py:18-27` 默认创建 `ingestion_run.db` 并调用 `ingest()`，`orchestrator.py:50-55` 无 dry-run 参数，`:127-128` 直接 `_save_items()`。
   影响：操作者仍可能运行旧脚本直接写入本地/目标 DB，不满足“默认 dry-run，显式操作才真实写入”的全局要求。
   复现：阅读上述文件；不要在生产环境运行 `scripts/run_ingestion.py`。
   最小修复建议：废弃或加硬 `scripts/run_ingestion.py`，要求显式 `--live`；核心 `ingest()` 增加 dry-run/no-write 模式或明确限制为内部 API。

### P1：必须修复

1. 来源白名单未接入运行时门禁
   证据：`docs/13-releases/v0.1.0-literature-compliance-release.md:104-106` 承认 whitelist not enforced；`orchestrator.py` 仅使用 `SOURCES` 静态 dict；未读取 `backend/app/config/source_whitelist.yaml`。
   影响：非法/未列入来源不能由运行时默认拒绝。
   最小修复建议：在采集发起前加载白名单并强制 `metadata_allowed/fulltext_allowed/default_policy`，测试 D 类和未知来源。

2. 试采集种子不满足本验收要求且噪声偏高
   证据：`scripts/trial_run_ingestion.py:38-59` 缺少精确 `甲乙经`、`A-B Classic of Acupuncture and Moxibustion`、`Systematic Classic of Acupuncture and Moxibustion`；真实 Crossref 样本多条无关法律/工程/企业工会结果。
   影响：小规模试采集结果不可控，人工审核负担高。
   最小修复建议：拆分核心/扩展/探索种子；核心默认只跑高精度词；对 Crossref 加 title/subject 后过滤或降低默认范围。

3. 失败路径统计不完整
   证据：内存探针显示 timeout 失败正确；空结果为成功；批内重复不计入 `duplicates_skipped`；`LiteratureItem.try_create()` 对无效结果返回 `None`，未增加失败计数。
   影响：dry-run 报告可能低估解析失败和重复问题。
   最小修复建议：为 dropped invalid item、batch duplicate、cross-source duplicate 分别计数并输出。

4. Release 文档测试基线与实测不一致
   证据：release 文档 `:100` 写 full suite 823 pass；实测为 972 passed, 13 skipped, 1 xfailed。
   影响：文档不是当前可复现结果。
   最小修复建议：用本次命令输出更新 release 文档。

5. 操作手册路径和正式写入步骤不够安全
   证据：手册 `:88-100` 允许 `--live` 并提示生产 PostgreSQL；`:147` 建议将 trial DB 导入 staging；没有强制备份确认、二次确认、记录变更窗口和回滚 SQL 边界。
   影响：操作者可能误把试运行切到生产写入。
   最小修复建议：默认禁止生产 URL；`--live` 只允许 staging/trial DB，生产写入需单独 runbook 和审批。

### P2：可延期

1. release 文件目录与本指令期望不一致
   证据：实际为 `docs/13-releases/`；本报告按要求写入 `docs/13-release/`。
   影响：自动化/人工查找路径不一致。
   最小修复建议：统一 release 目录命名并更新引用。

2. 本轮新增测试质量偏弱
   证据：`tests/unit/test_trial_run.py` 多为导入/字符串扫描；没有真实 DB 前后快照断言；没有文件系统/向量库副作用断言；没有真实失败路径覆盖。
   影响：测试可辅助防回归，但不能自证 dry-run 安全。
   最小修复建议：增加 temp DB 文件不存在、业务表计数不变、失败路径计数、批内/跨源重复、非法来源等测试。

## 7. 最终放行判断

是否允许进入小规模真实数据试采集：**否**
是否允许关闭 dry-run：**否**
是否允许大规模全网采集：**否**
是否允许进入正式生产持续采集：**否**

允许的下一步仅限：修复 P0/P1 后重新提交、创建真实 tag、重跑本报告中的全部命令，并重新进行 Codex 验收。dry-run 脚本的零污染实测可以作为后续验收的正向证据，但不能抵消发布归档、tag、lint、白名单运行时门禁和全局默认 dry-run 的阻塞项。
