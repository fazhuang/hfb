# 文献采集来源政策 (Literature Source Policy)

> 文档编号: 07-compliance-001
> 版本: 0.1.0
> 最后更新: 2026-07-10
> 对应配置文件: `backend/app/config/source_whitelist.yaml`

## 1. 目的与适用范围

本文档定义本系统在文献数据采集过程中的来源分类标准、合规规则和操作限制。所有文献数据采集功能必须遵守本文档及对应的白名单配置文件。

## 2. 来源分类

| 类别 | 名称 | 元数据采集 | 全文采集 | 人工审核 | 描述 |
|------|------|-----------|---------|---------|------|
| **A** | 开放获取源 | ✓ | ✓ | 否 | 可自由采集元数据和开放全文 |
| **B** | 商业数据库 | ✓ | ✗ | 否 | 仅可采集元数据和外链 |
| **C** | 待审核源 | ✓ | ✗ | **是** | 需人工审核后方可决定采集范围 |
| **D** | 禁止源 | ✗ | ✗ | — | 绝对禁止，不得以任何方式采集 |

### 2.1 A 类 — 开放获取源

可采集元数据和全文内容。包括：

- **学术索引平台**：OpenAlex、Crossref（CC0 / 开放 API）
- **开放获取聚合**：CORE（全球 OA 全文聚合）
- **生物医学库**：PubMed、Europe PMC（NIH/NLM 维护的公共数据库）
- **数字存档**：Internet Archive（公共领域数字资源）
- **机构知识库**：大学开放的 DSpace、EPrints 等（需逐个确认 OA 声明）
- **古籍平台**：公共领域古籍（中国哲学书电子化计划等）

**合规依据**：这些来源的数据属于公共领域或采用 CC0/CC-BY 等开放许可，明确授权信息采集和再利用。

### 2.2 B 类 — 商业数据库

仅可采集元数据（标题、作者、摘要、关键词、DOI/链接），**禁止**下载、缓存或索引全文。

- **中文数据库**：知网 (CNKI)、万方、维普、超星
- **古籍商业库**：中华经典古籍库
- **商业电子书**：京东读书、Kindle 商店等
- **高校订阅库**：IEEE Xplore、Elsevier、Springer、JSTOR

**合规依据**：元数据（标题、作者、摘要等）属于不构成实质性替代使用的事实性信息，可用于学术索引。全文受版权和订阅协议保护，采集全文属于侵犯版权和违反服务条款的行为。

### 2.3 C 类 — 待审核源

默认仅可采集元数据，全文采集需经人工审核。

- **地方图书馆资源**：数字化馆藏，需逐项审核版权状态
- **个人博客/自媒体**：内容可信度和版权合规性需个案评估
- **论坛资料**：需审核是否涉及未经授权的转载
- **公众号文章**：需评估来源可靠性和合规性
- **网盘资源**：默认禁止采集，仅经人工审核确认授权后可采集

**审核流程**：
1. 提交采集申请，说明来源 URL、预期采集范围、使用目的
2. 审核人确认版权状态、许可条款和内容可信度
3. 审核通过后，在白名单中新增具体条目（不得用通配符泛指）
4. 审核记录归档保存，支持后续审计

### 2.4 D 类 — 禁止源

**绝对禁止**，不得以任何方式索引、链接或采集。

- 盗版 PDF 站点（Sci-Hub、LibGen 等）
- 无授权的数字化扫描件
- 需要绕过登录、付费墙或地域限制才能获取的资源
- 破解版或盗版数据库
- 未经授权的镜像站点

## 3. 采集行为准则

### 3.1 强制性约束

1. **不写真实爬虫** — 系统仅定义数据模型和接口契约，由授权子系统按合规要求实现
2. **不绕过登录** — 不通过技术手段绕过目标网站的登录、付费墙或访问控制
3. **不访问付费全文** — 不下载、缓存或索引付费数据库的全文内容
4. **不批量下载商业论文** — 不进行任何形式的批量下载
5. **合规说明** — 每个来源必须有关联的合规备注，记录许可依据
6. **尊重 robots.txt** — 遵守目标网站的爬虫协议和 API 速率限制
7. **用途限制** — 采集数据仅用于学术研究索引，不转售或商业化使用

### 3.2 技术实现约束

- 元数据采集接口仅设计为返回结构化摘要信息，不得包含下载全文的能力
- 全文采集功能仅对 A 类来源启用，且必须在配置中显式声明
- 所有采集请求必须携带 User-Agent 标识，明确请求来源
- API 调用必须设置合理的速率限制，避免对目标服务造成负担

## 4. 数据存储与审计

| 来源类别 | 元数据存储 | 全文存储 | 审计要求 |
|---------|----------|---------|---------|
| A | ✓ 本地缓存 | ✓ 标注出处和许可 | 记录采集时间、来源、许可 |
| B | ✓ 仅元数据+外链 | ✗ 禁止缓存 | 记录采集时间、来源 |
| C (未审核) | ✓ 仅元数据+外链 | ✗ 禁止缓存 | 标注"待审核"状态 |
| C (已审核) | 按审核结果 | 按审核结果 | 记录审核决定和依据 |
| D | ✗ 禁止存储 | ✗ 禁止存储 | — |

所有存储的数据需记录以下审计字段：
- `collected_at` — 采集时间
- `source_url` — 来源 URL
- `license_basis` — 许可依据
- `review_status` — 审核状态（C 类适用）
- `reviewed_by` — 审核人（C 类适用）

## 5. 白名单维护

### 5.1 新增来源

1. 提交新增来源申请，包含：名称、域名、建议分类、合规依据
2. 审批通过后更新 `source_whitelist.yaml`
3. A/B/D 类由管理员直接审批；C 类需附审核人评估意见
4. 新增条目提交 git，保留变更历史

### 5.2 分类变更

1. 来源的开放获取政策可能变更（如期刊转为 OA）
2. 需重新提交分类变更申请并附新的合规依据
3. 历史数据的处理方式需在变更中说明（保留、转换或删除）
4. 变更记录归档

### 5.3 默认规则

未列入白名单的来源，默认按照以下策略处理：

- `metadata_allowed: false`
- `fulltext_allowed: false`
- `requires_manual_review: false`

即：默认禁止采集。需新增来源时，必须经过审批流程。
