# Research Lead 来源准入清单填写指引

---

> **性质:** 本指引是 [0306 准入清单](0306_Manual_Research_Source_Admission_Checklist.md) 的**填写格式教学文档**，不是准入清单本身，也不是准入清单的替代品。
> **边界:** 所有示例均以**类别特征占位符**（如 `[官修丛书影印本]`）示范填写格式，**不列任何具体真实来源**。**严禁将本指引中的占位文字抄入 0306 准入清单** —— 准入清单必须由 Research Lead 基于真实、可追溯、已授权的来源亲自填写。

---

## 1. 使用方式

Research Lead 填写 0306 §3 的 13 行时，对照本指引逐字段检查。每个字段给出：

- **语义** —— 该字段表达什么（引用 0306 §3.4）。
- **格式示范** —— 用类别特征占位符示范的填写样式（仅供理解格式）。
- **常见错误** —— 会被视为未完成的写法。
- **检查点** —— 提交前自检问题。

---

## 2. 字段 1：来源 URI / 馆藏标识

**语义**：该来源的可解析标识符（URL 或馆藏索书号）。

**格式示范**：

| 来源类型 | 示范（类别特征，非真实来源） |
| -------- | ---------------------------- |
| 古籍版本 | `[某图书馆]藏[明万历刊本]，索书号 [馆藏编号]` |
| 研究文献 | `https://doi.org/[DOI 编号]` 或 `[出版社]《[书名]》[第 N 版]` |
| 馆藏资料 | `[某机构]数字化馆藏，访问链接 [URL]，馆藏编号 [编号]` |

**常见错误**：

- 留空。
- 只写「某书」「某版本」而无 URI/索书号。
- 写一个无法解析或无法访问的链接。

**检查点**：第三方能否仅凭此字段定位到该来源的物理或数字副本？

---

## 3. 字段 2：版权/授权依据

**语义**：确立使用和导入该来源的法律依据。

**格式示范**：

| 授权类型 | 示范（类别特征） |
| -------- | ---------------- |
| 公有领域 | `公有领域（作者逝世超过 100 年）` |
| CC 许可 | `CC BY 4.0（出处 [URL]，条款 [URL]）` |
| 机构授权 | `机构授权书编号 [编号]，授权范围 [范围]，授权方 [机构]` |
| 合理使用 | `合理使用（学术研究目的，限于元数据+摘要，不含全文）` |

**常见错误**：

- 写「待确认」「需核实」「版权状态未知」。
- 写「上传者确认已授权」——这是运行时上传的声明，不是来源准入的授权依据。
- 用 `N/A` 绕过（版权/授权是核心字段，禁止 `N/A`）。

**检查点**：若被要求出示授权文件，能否立即提供对应凭证？

---

## 4. 字段 3：版本标识

**语义**：版本学/文献学唯一标识。

**格式示范**：

| 来源类型 | 示范（类别特征） |
| -------- | ---------------- |
| 古籍版本 | `[朝代][年号]刊本，[藏板]，行款[每半叶行数]行[字数]字，[序跋信息]` |
| 研究文献 | `[出版社] [出版年]，第[版次]版，ISBN [编号]` |
| 馆藏资料 | `[机构][版本描述]，数字化批次 [批次号]` |

**常见错误**：

- 只写「古籍」「现代校注本」而无刊刻年代/版次。
- 无法区分该版本与其他版本（版本标识不唯一）。

**检查点**：该标识能否将该来源与同名异本明确区分？

---

## 5. 字段 4：导入范围

**语义**：该来源拟导入 HFB 的精确数据范围。

**格式示范**：

| 范围粒度 | 示范（类别特征） |
| -------- | ---------------- |
| 全卷 | `全卷 12 卷（卷 1-12）` |
| 选篇 | `选篇（仅 [某病证] 相关条文，共 [N] 条）` |
| 元数据+摘要 | `元数据+摘要（不导入全文）` |

**常见错误**：

- 写「全库导入」「全部内容」——模糊声明，禁止。
- 写「视情况而定」——无明确范围。

**检查点**：能否逐条列出拟导入的具体卷/篇/条清单？

---

## 6. 字段 5：SourceRef → Evidence → Citation 绑定计划

**语义**：该来源导入后在 HFB 数据模型中逐条建立完整证据绑定链的**预先规划**（导入前可审计，非已验证事实）。

**格式示范**（类别特征，非数据库 ID）：

```
SourceRef(url=<来源 URI>) → Evidence(source_ref_id=<待创建>,
source_passage_id=<预期 Passage：按 [定位规则] 定位，或待创建 Passage P-新>)
→ Citation(evidence_id=<待创建>)，计划 N 条 Citation。
```

**关键约束**：

- **禁止**在导入前填写实际的 `source_ref_id` / `evidence_id` / `citation_id` 数据库记录值（这些记录在 3C 导入后才存在）。
- 用「<待创建>」或「定位规则」表达预期对应关系。
- 计划须包含：外部来源标识、拟绑定范围、预期 Passage 定位规则或待创建对象、预期绑定数量。

**常见错误**：

- 填写 `SR-XX`、`E-XX`、`P-XX` 等看似数据库 ID 的占位符（0306 明确禁止占位 ID）。
- 只写「建立完整证据链」而无逐条规划。
- 用 `N/A` 绕过（绑定计划是核心字段，禁止 `N/A`）。

**检查点**：Codex 能否仅凭此计划，独立判断每条来源的三层绑定是否一致、可执行、可审计？

---

## 7. 字段 6：风险说明

**语义**：该来源已知或潜在的数据质量/合规风险。

**格式示范**：

| 风险类别 | 示范（类别特征） |
| -------- | ---------------- |
| 版本分歧 | `该版本与通行本存在文字差异，涉及穴位归属时不做确定性同一化` |
| 避讳改字 | `清乾隆馆臣校勘干预（避讳改字、异体字规范），标注版本来源，不做推定统合` |
| 编码不一致 | `数字化 API 多次获取同一 URL 可能返回不同文字，以最近一次 fetch 为准` |
| 无已知风险 | `暂无（基于 [核查方式] 核查）` |

**常见错误**：

- 留空（即使无风险，也须写明「暂无」并注明核查依据）。
- 泛泛写「可能有风险」而无具体说明。

**检查点**：该风险是否具体到「影响什么判定、采取什么缓解措施」？

---

## 8. 完整行格式示范（仅供理解，禁止抄入 0306）

以下一行示范了 7 个字段的**格式组合**，全部为类别特征占位符，**不构成任何真实来源，严禁抄入准入清单**：

| 字段 | 示范内容 |
| ----- | -------- |
| 来源 URI / 馆藏标识 | `[某公立图书馆]藏[明万历刊本]，索书号 [馆藏编号]` |
| 版权/授权依据 | `公有领域（作者逝世超过 100 年）` |
| 版本标识 | `明万历 [年份] 刊本，[藏板]，行款 [N] 行 [N] 字，[序跋]` |
| 导入范围 | `选篇（仅 [某病证] 相关条文，共 [N] 条）` |
| 绑定计划 | `SourceRef(url=<来源 URI>) → Evidence(source_ref_id=<待创建>, source_passage_id=<按 [定位规则] 定位>) → Citation(evidence_id=<待创建>)，计划 [N] 条 Citation` |
| 风险说明 | `该版本存在避讳改字，标注版本来源，不做推定统合` |
| 审核人 / 审核日期 | `<Research Lead 真实姓名>` / `YYYY-MM-DD` |

---

## 9. 提交前总检查

- [ ] 13 行全部填写，无空白单元格。
- [ ] 无 `N/A` 绕过核心字段（来源标识、版权/授权、导入范围、绑定计划、签署）。
- [ ] 绑定计划不含占位数据库 ID（`SR-XX` 等）。
- [ ] 每条来源可被独立第三方定位与核实。
- [ ] 每条版权/授权依据可出示对应凭证。
- [ ] §4 由 Research Lead 真实签署（姓名 + 日期），技术负责人确认可行性并签署。
