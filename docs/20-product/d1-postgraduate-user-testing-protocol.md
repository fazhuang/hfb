## 1. 测试定位与合规边界声明

### 1.1 协议目的

本协议旨在通过真实研究生用户在真实 UI 路径下的操作，评估以下维度：

- **操作流畅度**：用户能否独立完成从课题建立到报告导出的完整研究链路，无外部提示。
- **交互直觉**：导航结构、搜索入口、AI 辅助触发点、引用溯源路径是否符合人文学科研究者的心智模型。
- **证据理解力**：用户能否正确区分 Citation（引用条目）、Evidence（证据锚点）与 SourceRef（来源段落引用）三层身份链，并用于学术判断。

### 1.2 合规边界

本协议严格限定为前端交互可用性测试，**不授权**以下任何行为：

- 真实未经许可的学术数据导入或批量文献抓取。
- 系统安全审计、渗透测试或 RBAC 鉴权测试。
- 性能压测、并发负载测试或资源耗尽测试。
- 数据准入校验或后端 API 契约验证。
- Phase 10 最终验收（Phase 10 由独立卡 D2 覆盖）。

**隔离边界声明**：D1 是前端可用性观察协议，不替代、也不构成安全验收、RBAC 验收、数据准入验收或 Phase 10/D2 发布验收。D1 PASS 不解除 `BLOCK_RELEASE`。

**数据边界**：D1 仅可使用 PO 批准的合成或已脱敏、不可回溯至真实个人或真实未公开学术材料的测试数据。严禁使用生产真实学术语料、真实用户课题、真实导出文件及任何未获书面批准的数据。本协议各任务中提及的课题名称、描述、关键词、文献及段落均为预置合成测试样例，仅供可用性观察使用。

本协议产生的所有发现应标记为 `source: D1-user-testing`，与自动化测试、Codex 验收证据明确区分。

## 3. 研究者 Canonical 任务链路

以下任务按真实 UI 导航顺序编排，**严禁**使用 URL 直达、Token 注入、Mock 接口控制、控制台手动注入状态或任何后台绕过方式。所有步骤必须从可见导航元素（侧边栏、顶栏、页面内按钮/链接）进入。所有任务使用的课题名称、描述、关键词、文献及段落均为 PO 批准的预置合成测试样例。

### 任务 1：课题建立与工作区导航

| 步骤 | 操作描述                                          | 观察点                          |
| ---- | ------------------------------------------------- | ------------------------------- |
| 1.1  | 从登录后首屏，通过可见导航进入工作区（Workspace） | 能否独立找到入口                |
| 1.2  | 创建一个新的研究课题，填写课题名称与可选描述      | 表单理解度、必填/选填辨识       |
| 1.3  | 在课题列表中定位刚创建的课题并进入                | 列表扫描效率、排序/筛选使用情况 |

### 任务 2：关键字与条件搜索

| 步骤 | 操作描述                                                   | 观察点                              |
| ---- | ---------------------------------------------------------- | ----------------------------------- |
| 2.1  | 在课题内定位搜索入口（搜索框或搜索按钮）                   | 搜索入口可见性                      |
| 2.2  | 输入一个古籍关键词（如"伤寒"），执行搜索                   | 输入体验、自动补全/建议的发现与使用 |
| 2.3  | 使用筛选条件（如文献来源、朝代、版本）缩小结果范围         | 筛选控件的可理解性                  |
| 2.4  | 浏览搜索结果列表，识别条目信息（标题、作者、年代、相关度） | 结果卡片信息架构的直觉理解          |

### 任务 3：Reader 阅读与精准段落定位

| 步骤 | 操作描述                                                         | 观察点                            |
| ---- | ---------------------------------------------------------------- | --------------------------------- |
| 3.1  | 从搜索结果中打开一条文献，进入 Reader 阅读视图                   | 能否找到并点击正确的打开入口      |
| 3.2  | 在原文中滚动浏览，定位到包含目标关键词的具体段落                 | 滚动性能感知、目次/锚点导航的使用 |
| 3.3  | 使用段落定位功能（如目次跳转、段落高亮、搜索定位）跳转到指定段落 | 定位工具的发现与使用效率          |
| 3.4  | 查看段落关联的元数据（出处、版本、页码）                         | 元数据展示的完整性与可读性        |

### 任务 4：触发 AI 辅助分析

| 步骤 | 操作描述                                       | 观察点                       |
| ---- | ---------------------------------------------- | ---------------------------- |
| 4.1  | 在 Reader 中找到 AI 辅助分析触发入口           | 入口可见性与位置合理性       |
| 4.2  | 触发 AI 分析，观察分析结果加载过程             | 加载状态反馈、等待时间容忍度 |
| 4.3  | 阅读 AI 分析结果（如释义、翻译、相关文献推荐） | 结果可读性、可信度感知       |
| 4.4  | 如有交互能力，追问或调整分析范围               | 对话/交互模式的发现与使用    |

### 任务 5：Citation / Evidence / SourceRef 引用溯源链校验

| 步骤 | 操作描述                                                                  | 观察点                                                  |
| ---- | ------------------------------------------------------------------------- | ------------------------------------------------------- |
| 5.1  | 在 Reader 中找到引用操作入口（如"引用"按钮或 Citation 区域）              | 引用入口的视觉显著性                                    |
| 5.2  | 查看一条 Citation（引用条目）的完整信息（作者、标题、版本、章节）         | Citation 元数据完整性理解                               |
| 5.3  | 从 Citation 追溯到关联的 Evidence（证据锚点，即原文中对应的具体段落引用） | Evidence 关联关系是否可被用户理解                       |
| 5.4  | 从 Evidence 追溯到 SourceRef（来源段落引用，即原文出处中的精确段落链接）  | 三层身份链（Citation → Evidence → SourceRef）的完整遍历 |
| 5.5  | 通过 SourceRef 链接返回 Reader 中对应原文位置，验证引用准确性             | 溯源闭环的闭合体验                                      |

### 任务 6：报告生成与导出

| 步骤 | 操作描述                                                       | 观察点                         |
| ---- | -------------------------------------------------------------- | ------------------------------ |
| 6.1  | 在课题内找到报告生成入口（如工具栏中的"生成报告"或"导出"按钮） | 入口可见性                     |
| 6.2  | 选择报告范围（如当前课题的全部引用、选中引用、含 AI 分析）     | 选项的可理解性                 |
| 6.3  | 生成并预览报告                                                 | 报告格式、内容完整性、加载时间 |
| 6.4  | 导出报告（如 PDF、Markdown 或打印视图）                        | 导出格式可用性、导出文件完整性 |

### 任务 7：跨任务导航与状态保持

| 步骤 | 操作描述                                     | 观察点                        |
| ---- | -------------------------------------------- | ----------------------------- |
| 7.1  | 从 Reader 返回搜索结果列表，确认搜索条件保留 | 返回导航时状态是否丢失        |
| 7.2  | 在多个课题间切换，确认各课题独立状态         | 课题隔离感                    |
| 7.3  | 使用浏览器后退/前进导航                      | 浏览器导航与 SPA 路由的一致性 |

## 4. 异常与边缘场景观察矩阵

### 4.1 弱网 / 高延迟

| 场景                            | 模拟方式                                        | 观察指标                                           |
| ------------------------------- | ----------------------------------------------- | -------------------------------------------------- |
| 慢速 3G（~400ms RTT, ~400kbps） | 浏览器 DevTools Network throttling              | Loading 指示器是否及时出现、是否有骨架屏/占位符    |
| 断续网络                        | DevTools Network throttling + 间歇 Offline 切换 | 超时后的友好提示文案、重试按钮/自动重试行为        |
| 搜索请求延迟 > 5s               | 网络节流                                        | 用户是否重复点击（需防重复提交）、取消操作的可用性 |
| 长文本加载延迟                  | 网络节流                                        | 渐进式渲染还是白屏等待、滚动位置保持               |

### 4.2 AI 服务异常

AI 异常场景仅观察 PO 批准的 staging 环境中自然可复现的错误状态。观察记录员不得使用关闭 AI 服务、注入错误、注入延迟或任何后端/前端 Mock 手段人为触发。若某异常在测试期间自然发生，记录观察结果；若不可复现，记录"未触发，不以 Mock 替代"。

| 场景                              | 触发条件                                                    | 观察指标                                                                         |
| --------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| AI 响应失败（500/503）            | 仅观察自然发生的服务端错误                                  | 错误提示是否易懂、是否提供可见重试入口、用户仅通过可见重试按钮发起局部重试的结果 |
| AI 响应超时                       | 仅通过浏览器 DevTools Network throttling 观察               | 超时后用户当前输入/上下文是否保留（用户无需重新输入问题）                        |
| AI 响应中断（部分流式输出后断开） | 仅通过浏览器 DevTools Network throttling + Offline 切换观察 | 已接收的部分内容是否保留可见、中断提示是否明确                                   |
| 连续重试 3 次仍失败               | 仅记录用户主动通过可见重试按钮连续重试 3 次后的自然结果     | 是否有降级建议（如"稍后再试"或离线参考方案）                                     |

### 4.3 界面适配与无障碍

| 场景               | 模拟方式                                         | 观察指标                                                                           |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 200% 视图放大      | 仅浏览器原生缩放至 200%                          | 布局无溢出、文字不截断、按钮可点击、导航栏不遮挡内容                               |
| 375×812 移动端视口 | 浏览器 DevTools 设为 iPhone X/SE 尺寸            | 触控目标 ≥ 44×44 CSS px、横滑无溢出、底部不被固定元素遮挡                          |
| 繁简体切换         | 通过应用内切换（如有）或浏览器语言设置           | 切换后搜索准确性（繁简关键词应等效命中）、UI 文案全部切换无残留                    |
| 字号调整           | 仅放大应用内正文字号设置（不依赖浏览器缩放）     | 行高同步调整、表格/引用块不溢出、段落间距保持比例                                  |
| 键盘导航           | 仅使用 Tab / Shift+Tab / Enter / Escape / 方向键 | 所有交互元素可聚焦、焦点顺序合乎视觉逻辑、焦点指示器始终可见、模态框可 Escape 关闭 |

## 5. 观察者记录表与评估指标体系

### 5.1 定量指标

| 指标                    | 定义                                                                                                                                         | 记录方式                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 任务完成率（Pass/Fail） | 用户在无外部提示下完成预设目标。Pass 须满足：到达目标页面/状态 + 可口头确认任务达成。Fail 包含：放弃、需要提示、执行了非目标路径且未自我纠正 | 每个任务/子步骤独立记录 |
| 完成时长（秒）          | 从用户表示"开始"到用户口头确认完成（或观察者判定完成/放弃）的墙钟时间。不含观察者讲解和中间提问时间                                          | 秒表记录，精确到秒      |
| 错误恢复成功率          | 用户进入非目标路径后，是否在无提示下自行识别并回到正确路径。成功率 = 自行恢复次数 /（自行恢复次数 + 需提示次数）                             | 每个偏离事件记录        |
| 首次点击正确率          | 用户在每个关键交互节点（搜索入口、Reader 打开、AI 触发、引用溯源）第一次点击/操作即命中正确目标的比率                                        | 每个节点记录正确/错误   |

### 5.2 定性指标

| 指标               | 评分范围 | 锚定描述                                                                                                               |
| ------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| 证据理解清晰度     | 1–5 分   | 1 = 无法区分 Citation/Evidence/SourceRef；3 = 能区分但无法解释差异；5 = 能准确解释三层身份链并判断引用准确性           |
| 主观操作信心度     | 1–5 分   | 1 = 每步都需要确认/犹豫；3 = 大部分步骤自信但关键分支需要思考；5 = 全程流畅，知道自己"在哪里"和"下一步该做什么"        |
| 导航心智模型匹配度 | 1–5 分   | 1 = 导航结构不符合预期，频繁迷路；3 = 基本匹配，个别页面入口位置意外；5 = 导航层级与预期完全一致，无需思考即可定位     |
| AI 辅助可信度感知  | 1–5 分   | 1 = 不信任 AI 输出，认为不可靠；3 = 部分信任，会交叉验证；5 = 高度信任，愿意直接引用（观察者须记录用户口头表述的原话） |
| 整体满意度         | 1–5 分   | 测试结束后的单一主观评分：1 = 不会再次使用；3 = 如有改进可能使用；5 = 愿意推荐给同行                                   |

### 5.3 阻碍点描述（Blockers）

观察记录员须以自由文本记录每个阻碍点的以下要素。所有自由文本字段须遵守第 2.2 节强制脱敏规则——不得记录姓名、机构、导师、联系方式、账号名、课题细节或其他可识别信息；如受试者主动说出，以 `[已移除身份信息]` 替换：

- **发生位置**：页面/组件名称、当前步骤编号
- **用户行为**：用户尝试了什么、说了什么（脱敏后引用）
- **期望行为**：设计预期的正确路径
- **后果**：用户放弃 / 需要提示 / 绕过 / 误以为任务完成
- **严重性分级**：P0 / P1 / P2 / P3（见 5.4）

### 5.4 问题严重性分级矩阵

| 级别   | 名称         | 定义                                                 | 示例                                                                                     |
| ------ | ------------ | ---------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **P0** | 致命阻塞     | 流程中断，用户无法继续或丢失数据，任务直接 Fail      | 点击"生成报告"后白屏、导出文件损坏、搜索无结果且无提示                                   |
| **P1** | 主要功能异常 | 核心功能可用但存在显著障碍，用户需绕过或重试才能完成 | AI 分析按钮不可见需滚动才发现、Reader 段落定位功能不在预期位置、溯源链某环节断裂用户困惑 |
| **P2** | 次要体验问题 | 不影响任务完成但增加认知负荷或操作步骤               | 加载无反馈动画、筛选条件重置后不保留、错误提示过于技术化                                 |
| **P3** | 建议性优化   | 功能正常，用户体验有提升空间                         | 按钮文案不够直观、信息密度过高/过低、快捷键缺失                                          |

## 6. 测试执行规范

### 6.1 测试前准备

1. 确认测试用账号已创建（标准研究生角色，非管理员），凭据在手边备用。
2. 确认测试环境为生产等价部署或经 PO 批准的 staging 环境。
3. 准备观察记录表（纸质或离线电子版）。
4. 确认浏览器 DevTools 已配置好网络节流预设（Slow 3G、Offline 切换）。
5. 确认移动端或响应式测试视口预设已就绪（375×812）。
6. 朗读知情同意书，取得口头确认并记录为"已确认"（不记录精确时间）。

### 6.2 测试中规范

- **观察者角色**：静默观察，不提供操作提示。仅在用户明确表示放弃或请求帮助时，先问"您认为下一步应该在哪里？"再决定是否介入。
- **出声思维（Think Aloud）**：鼓励用户在操作过程中说出自己的想法（"我现在在找…""我以为这里会有…""这个按钮的意思是不是…"）。观察者仅以"嗯"或点头回应，不引导。
- **中断条件**：用户连续 3 分钟无进展且无出声、用户主动要求终止、系统崩溃或数据丢失。
- **禁止行为**：观察者不得代替用户操作、不得用手指屏幕、不得说"试试点这里"。

### 6.3 测试后流程

1. 立即请用户完成定性评分（5.2 节五项 1–5 分）。
2. 开放式访谈（5 分钟以内）："哪个环节最困惑？""哪个功能最有价值？""如果只能改一件事，改什么？"
3. 感谢受试者，确认数据将匿名处理。
4. 观察者在 24 小时内整理观察记录，将阻碍点录入严重性分级矩阵。

### 6.4 建议样本量

- **最低**：5 名研究生用户（人文学科背景，具备古籍阅读能力）。
- **建议**：8–12 名，覆盖不同院校背景和数字素养水平。
- **招募渠道**：通过导师推荐或学术社群邀请，不得通过平台用户数据库直接联系。

## 7. 报告输出规范

测试完成后，汇总报告应包含：

1. **执行摘要**：测试人数、总体完成率、关键发现（≤ 5 条 P0/P1）。
2. **按任务统计**：每任务的 Pass/Fail 数、平均时长、首次点击正确率。
3. **定性评分汇总**：五项评分的中位数与分布。
4. **阻碍点清单**：按严重性（P0 → P3）排序，逐项附受试者编号、发生位置、脱敏后用户反馈、建议修复方向。
5. **异常场景观察汇总**：弱网、AI 失败、适配、键盘导航的逐项发现。
6. **严重性分布图**：P0/P1/P2/P3 数量柱状图。

报告文件命名：`docs/20-product/d1-postgraduate-testing-report-YYYY-MM-DD.md`
