# v0.1.0-literature-compliance — Release Notes

**Tag:** `v0.1.0-literature-compliance` (to be created after checklist sign-off)
**Date:** 2026-07-11
**Branch:** master
**Base commit:** `804004a` (approximate — workspace has staged fixes)

## Scope

This release archives the 皇甫谧 (Huangfu Mi) literature ingestion module as
verified by the Gemini academic review (Context 24), packaging metadata
ingestion, full-text compliance gates, RAG evidence binding, and the
literature frontend into a named release point.

**No new features are included.** This is an archival + trial-readiness
release.

## What's Included

### Metadata Ingestion Pipeline (5 sources)

- `openalex` — OpenAlex REST API with retry/backoff (403 handling)
- `crossref` — Crossref REST API
- `core` — CORE API v3 (rate-limited without API key)
- `pubmed` — Europe PMC primary + NCBI E-utilities fallback, defusedxml
- `internet_archive` — IA advanced text search
- 7 bilingual search queries (中文/English)
- DOI + title/year two-layer dedup
- `IngestionJob` per-source-per-query audit trail

### Full-Text Compliance (Context 21 — PASS)

- `IngestionService` with copyright gate: default-deny on unknown status
- Allowed: `public_domain`, `open_access`, `licensed`, `user_uploaded_with_permission`
- Forbidden: `unknown`, `metadata_only`, `forbidden_fulltext`, `commercial_restricted`, `pirated`
- SHA-256 content checksum on every ingested document
- `FulltextIngestionAudit` persistent audit table
- Soft-delete withdrawal: Document + all chunks, audit logged
- Shared `_compliance_clauses()` predicate between RetrievalService and EvidenceRAGService

### RAG Evidence Binding (Context 22 — PASS)

- `rag_enabled` gate — only reviewed + compliant documents enter RAG
- Per-chunk provenance metadata (paragraph_index, page_number, ocr_confidence)
- Deterministic retrieval scoring (hit-rate 0.5 + coverage 0.3 + frequency 0.2)
- `withdrawn_at IS NULL` guard on all retrieval paths

### Literature Frontend (Context 23 — PASS)

- Three-tier auth (user / admin / superadmin)
- Literature list + detail views with copyright status display
- Admin review queue + source policy management
- Ingestion task audit view

### Security & Compliance Artifacts

- `source_whitelist.yaml` — 4-tier source classification (A/B/C/D)
- SSRF protection inherited from global middleware
- Source code compliance: no PDF download logic, no paywall bypass
- `defusedxml` for PubMed XML parsing (XXE-safe)

## Known Limitations (NOT blocking)

1. **Source whitelist not enforced at runtime.** `source_whitelist.yaml` is a
   policy document; it is not loaded or checked by backend services. Enforcement
   is procedural (manual review).
2. **Metadata ingestion has no persistent audit table.** `IngestionJob` is
   in-memory only. `Paper` model lacks `copyright_status`/`rag_enabled` fields.
3. **No REST endpoint for triggering metadata ingestion.** Callable only via
   `orchestrator.ingest()` Python API.
4. **API auth deferred on `/search/ingest`.** Write endpoints lack backend
   permission checks; rely on frontend gateway isolation. Tracked as
   `ponytail: auth deferred to post-Day-2 hardening`.
5. **`Paper` ↔ `Document` link gap.** Metadata ingestion creates `Paper`
   records; full-text ingestion creates `Document` records. No explicit
   relationship between them.
6. **CORE API key not configured.** Unauthenticated CORE requests hit rate
   limits on Chinese queries. Set `CORE_API_KEY` in `.env` for stable access.
7. **OpenAlex intermittent 403.** Cloudflare bot detection triggers on some
   queries despite retry/backoff.
