## Code of Conduct

This project and everyone participating in it is governed by our [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code.

## Development Principles

1. **AI-Native Development**: This project is designed for AI-human collaboration. All code, documentation, and workflows should be structured for both human and AI consumption.
2. **Chinese-First Documentation**: Primary documentation is in Chinese (中文). Technical identifiers and code comments may use English.
3. **Monorepo Discipline**: All code lives in the monorepo. Cross-package changes must be coordinated.
4. **Testing Required**: All features require tests. No exceptions without ADR approval.

## Getting Started

```bash
# Clone the repository
git clone https://github.com/huangfumi/hfb.git
cd hfb

# Run setup script
make setup

# Start development environment
make dev
```

## Development Workflow

1. Pick an issue from GitHub Issues
2. Create a feature branch: `feature/###-description` or `fix/###-description`
3. Write code following our standards
4. Write tests
5. Run `make lint` and `make test`
6. Push and create a Pull Request

## AI Collaboration Workflow

This project embraces AI-assisted development:

1. **Prompt Templates**: Use templates from `/docs/09-prompts/` when working with AI
2. **AI Code Review**: AI tools may be used for initial code review, but human approval is always required for merge
3. **Generated Code Attribution**: Code significantly generated by AI should include an `@ai-generated` comment with the prompt reference
4. **Architecture Decisions**: All significant architecture decisions go through ADR process in `/docs/11-adr/`

## Coding Standards

### Python
- Use `ruff` for linting and formatting
- Type hints required for all function signatures
- Follow `mypy` strict mode
- 120 character line limit

### TypeScript / Vue
- Use `eslint` flat config
- `prettier` for formatting
- Vue 3 Composition API with `<script setup lang="ts">`
- 100 character line limit

### Markdown
- UTF-8 encoding
- LF line endings
- Chinese and English bilingual where appropriate
- One sentence per line for source readability

## Testing

- **Unit tests**: Every function/method
- **Integration tests**: Every API endpoint
- **E2E tests**: Every critical user flow
- Coverage targets: 80%+ for business logic, 90%+ for utilities

```bash
make test          # All tests
make test-unit     # Unit tests only
make test-e2e      # E2E tests only
```

## Documentation

- Architecture decisions: `/docs/11-adr/`
- API documentation: Auto-generated from OpenAPI
- Sprint notes: `/docs/08-sprints/`
- Chinese preferred for narrative docs, English for technical references

## Commit Guidelines

Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add user authentication module
fix: resolve database connection timeout
docs: update API documentation
ci: add GitHub Actions for testing
refactor: extract shared types to packages/types
test: add unit tests for ontology parser
```

## Pull Request Process

1. Ensure all CI checks pass
2. Update documentation if needed
3. Add CHANGELOG entry for notable changes
4. Request review from appropriate CODEOWNERS
5. At least one approving review required
6. Squash merge preferred
